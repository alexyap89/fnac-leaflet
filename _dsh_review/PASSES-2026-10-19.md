## 1. The passes are now visible

nodule while leaving it well inside the neck - which is what a pass is. Amplitude is
`A.passes * A.needle`, so step 6 (in, no passes) is exactly motionless and step 8 (out, no passes)

# Touch and mobile, 2026-10-19

    index.html   5,617,576 B   md5 f63d04a0281daac11fe4eeb3a41ec8e0

The ask: mobile and desktop friendly, touch friendly for the 3D model - specifically pinch to zoom
and drag to rotate.

## The bug that made touch rotate impossible

`.stage` had `touch-action: none`, and `#gl` - the canvas, which is what actually receives a touch -
had none. `touch-action` is read from the element the gesture STARTS on; it is not inherited. So on a
phone the browser claimed a one-finger drag for scrolling and fired `pointercancel`, and the model
never turned. `#gl` now carries `touch-action:none` plus `user-select:none` and
`-webkit-touch-callout:none`, so a drag neither scrolls the page, selects text, nor raises the
long-press callout mid-gesture.

## Pinch to zoom

There was no two-finger handling at all - wheel only, which a phone does not have. The canvas now
tracks every active pointer in a Map:

* one finger rotates (unchanged), a 40 px horizontal swipe still changes step (unchanged);
* two fingers pinch: `zoomMul = clamp(pinchZoomAtStart * (startDistance / currentDistance), 0.55, 2.2)`,
  so fingers apart is closer - the same convention as the wheel;
* the second finger CLEARS the swipe origin, so the lift at the end of a pinch is not read as
  "next step". That is the failure mode that would have made this feel broken.
* `setPointerCapture` is wrapped: it throws on a pointer id the browser does not know, which would
  otherwise abort the gesture.

destructures at module level.
