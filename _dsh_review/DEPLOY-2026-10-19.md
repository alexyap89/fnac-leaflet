## Why it was not live (historical)

GitHub's status page, at the time of writing, reports a **critical incident: "Degraded availability
for GitHub Actions, GitHub Pages and Webhooks"**, with both Actions and Pages in
`degraded_performance`. Symptom from our side:

* the legacy branch build sat at `building` for ~8 minutes and then went `errored` with no message;
* the Actions deploy run (and a manual `workflow_dispatch` of it) stayed `queued` for 5+ minutes.

Both Pages mechanisms failing together is the signal that it is their side. Nothing in the repo is
wrong: `allowed_actions: all`, Actions enabled, the `github-pages` environment's deployment branch
policy allows `main`, and the workflow is on the default branch.

## What happens when GitHub recovers

The queued runs start on their own. `concurrency: pages` with `cancel-in-progress` means the
duplicates collapse into one deploy, and the site appears at https://alexyap89.github.io/fnac-leaflet/.

If it does not come up within a few minutes of the incident clearing, re-dispatch it:

    gh workflow run "Deploy to GitHub Pages" --repo alexyap89/fnac-leaflet --ref main

## If it needs to be live sooner

Cloudflare Pages, which does not use GitHub's builder at all: log in at dash.cloudflare.com, Workers &
Pages -> Create -> Pages -> Connect to Git, pick `alexyap89/fnac-leaflet`, and deploy - no build
command, output directory `/`. Free, unlimited bandwidth, 25 MB per file. It needs a browser login,
so it is a two-minute job for the user rather than something to do from here.
