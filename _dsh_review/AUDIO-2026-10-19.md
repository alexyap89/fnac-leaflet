# Natural narration for the leaflet, 2026-10-19

The leaflet's spoken steps were macOS `say` Daniel - intelligible and completely flat, which is what
"the voice does not sound natural" means. They are now rendered by **OmniVoice** (a neural TTS) with
one reference voice cloned for every step, the same approach the sibling project pimri uses.

    index.html   5,527,027 B   md5 3798e96455839391b2e732e2e3a77555
    engine       omnivoice, k2-fsa/OmniVoice, cloned from the pRIMe-MRI reference voice
    clips        9, 104.5 s total, 628,956 B (was 130.1 s / 784,930 B)

## How it is produced

`tools/make_audio_leaflet.py --engine omnivoice` does the whole thing: it parses the step text out of
`src/app_app.js` (so the audio can never drift from the page), renders all nine clips against one
reference voice, levels each to -19 LUFS with a -1.5 dBTP cap, encodes to mp3, and writes the
manifest. The render is cached in `audio/en/leaflet/_neural_wav`, so re-encoding does not re-render.

Two properties are load-bearing and both came from the sibling project's write-up:

* **One reference voice for the whole set.** The model's auto mode picks a fresh speaker on every
  call, so clips rendered one at a time change voice between steps.
* **The reference transcript must be exact.** A wrong transcript does not fail loudly. It produces
  speech-shaped noise that passes a speech-likeness gate - see below.

**Voice quality - the spectral test the sibling project calibrated:**

| | `say` Daniel | OmniVoice |
|---|---|---|
| energy above 1 kHz | 12.1% | **32.5%** |
| energy below 400 Hz | 52.2% | **3.0%** |
| spectral centroid | 752 Hz | **994 Hz** |
| pace | 150 wpm | 175-199 wpm |

Formant synthesisers are bass-heavy with almost no high-frequency detail - that is the "flat" sound.
The neural clips carry 2.7x the high-frequency energy and a seventeenth of the low-frequency boom.

**Delivery - decoded in the browser from the built page:** all 9 inlined clips decode, durations
match the manifest (104.0 s against 104.45 s), byte counts match exactly, 9/9 steps still render,
zero console errors.

**Pace:** 175-199 wpm. The clips being replaced were 150 wpm and the first attempt at this rendered
at ~330 wpm, which is why the tool's pace gate was widened - it is a truncation check, not a tempo
prescription, and a natural read was failing it for being human.

## Two bugs found on the way, both mine

1. **Wrong reference transcript.** I took the transcript from the wrong narration entry, so every
   clip came back as nonsense - "Both the Jalmont and Cityature set apart Tanscary D..." - while
   passing the speech-likeness gate. Word recall against the page's text was 3-30%. Caught by
   transcribing the renders rather than trusting the spectral gate; the correct transcript was then
   obtained by transcribing the reference clip itself. The tool's own docstring warns about exactly
   this failure.
2. **The homebrew ffmpeg on this machine is broken** - it wants `libx265.216.dylib` and the
   installed x265 is 4.3, which ships `.217` - so every call dies on a dyld error. It broke the
   whole audio tool, not just the neural path: `duration()` swallowed the failure and returned 0.0
   for all nine clips, which the pace check reported as nine suspect clips instead of one broken
   tool. `ffmpeg_exe()` now prefers the system binary and falls back to the self-contained copy in
   the TTS venv; `duration()` raises instead of returning 0.0. **Your system ffmpeg is still broken
   for everything else** - worth `brew reinstall x265 ffmpeg`.

## Level

The neural set sits at -22.4 dBFS RMS against -19.5 for the `say` clips. Raising the target to -16
LUFS changed nothing: the gain is capped by the true-peak limit, so the difference is **crest
factor**, not a level error - `say` output is squashed to about 14 dB, natural speech runs nearer
21 dB. Compressing these to close the gap would undo the naturalness, so it is left alone. If it
sounds quiet on a phone, that is the honest fix - not more compression.

## Reverting

and `/tmp/heads/audio_say_original/`. To go back:
